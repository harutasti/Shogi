# 将棋アプリ Computer Use ブラックボックステスト仕様書

- 対象: <https://harutasti.github.io/Shogi/>
- 作成日: 2026-07-20
- テスト方式: Computer Useによる手動ブラックボックス／探索テスト
- 主目的: 不具合の検出に加え、初見ユーザーが迷う点、視認性、操作感、情報設計の改善候補を発見する

## 1. 基本方針

このテストではソースコードを判断材料にせず、利用者に見える画面と操作結果だけで評価する。

各テストで次の2種類を分けて記録する。

1. **適合性**: 操作に対して期待した結果になるか（Pass / Fail / Blocked）
2. **UX観察**: 動作は正しくても、迷い・見づらさ・遅さ・不安を感じる箇所がないか

改善案を先に決めつけず、まず観察事実を記録する。例:

- 悪い記録: 「ボタンを大きくするべき」
- 良い記録: 「初期画面で次に押すボタンを3秒以内に判断できなかった。『新規対局』とプレイヤー選択の関係が分からなかった」

## 2. 対象環境

最低限、以下の2条件で実施する。

| ID | 環境 | 目的 |
|---|---|---|
| ENV-01 | Chrome・通常のデスクトップ幅 | 基本操作、視覚階層、対局・解析フロー |
| ENV-02 | Chrome・狭いウィンドウ幅（スマートフォン相当） | 折り返し、横スクロール、タップ領域、盤と操作パネルの距離 |

各実行時に以下を記録する。

- 実行日時
- 公開URL
- 画面サイズのおおよその区分（desktop / narrow）
- 最初に表示された画面のスクリーンショット
- キャッシュ更新の有無

## 3. 判定と優先度

### 判定

- **Pass**: 期待結果を満たす
- **Fail**: 期待結果を満たさない
- **Blocked**: 前提となる操作や機能の問題で確認できない
- **N/A**: 今回の環境では対象外

### 改善優先度

- **P0**: データ損失、対局不能、公開不能
- **P1**: 主要フローを完了できない、盤面や指し手を誤認しやすい
- **P2**: 完了できるが迷いや強い不便がある
- **P3**: 見た目、文言、細かな操作感の改善

## 4. テスト用KIF

KIF読込・成駒・駒打ち・解析を一度に確認できるデータとして使用する。

```text
# ---- Computer Use テスト棋譜 ----
手合割：平手
先手：テスト先手
後手：テスト後手
手数----指手---------消費時間--
   1 ７六歩(77)   ( 0:00/00:00:00)
   2 ３四歩(33)   ( 0:00/00:00:00)
   3 ２二角成(88) ( 0:00/00:00:00)
   4 同　銀(31)   ( 0:00/00:00:00)
   5 ４五角打     ( 0:00/00:00:00)
   6 投了
まで5手で先手の勝ち
```

不正入力の確認には以下を使用する。

```text
手数----指手---------消費時間--
   1 ５五歩(77)
```

## 5. テストケース

### CU-01 初回表示と第一印象

**目的**: 読み込み成功と、初見での分かりやすさを確認する。

**手順**

1. 公開URLを新しいタブで開く。
2. 操作せずに画面全体を見る。
3. 5秒以内に「何のアプリか」「最初に何をすべきか」を判断する。
4. 盤、駒、持ち駒、手番、対局設定、棋譜、解析領域を確認する。

**期待結果**

- 将棋盤が9×9で表示される。
- 初期配置の駒が欠けず、壊れた画像がない。
- 先手・後手と現在の手番が分かる。
- 主要操作が画面内に存在する。
- 意図しない横スクロールや重なりがない。

**UX観察**

- 盤と操作パネルのどちらに最初に目が行くか。
- 「新規対局」を押す必要があるか直感的に分かるか。
- 先手／後手の設定と盤上の向きが対応して見えるか。
- 文字サイズ、コントラスト、余白、ボタンの優先順位は適切か。

### CU-02 対局開始とプレイヤー設定

**目的**: 対局条件を理解して開始できるか確認する。

**手順**

1. 先手を「あなた」、後手を「AI 初級」にする。
2. 「新規対局」を押す。
3. 状態表示と使用可能なボタンを確認する。
4. 先手と後手の設定を入れ替え、もう一度新規対局を開始する。

**期待結果**

- 選択した設定で新しい対局になる。
- 人間側の手番が明確に表示される。
- AIが先手の場合は自動で初手を指す。
- 棋譜、持ち駒、解析結果が初期化される。

**UX観察**

- 設定変更が即時適用なのか、新規対局後に適用なのか分かるか。
- 難易度名から強さの違いを想像できるか。
- 対局中の設定変更が可能に見えて混乱しないか。

### CU-03 駒選択・合法手・着手

**目的**: 基本の一手を迷わず指せるか確認する。

**手順**

1. 先手の歩を1枚選択する。
2. 合法な移動先の表示を確認する。
3. 選択を解除する。
4. 同じ歩を選び、合法な移動先へ動かす。
5. AIの応手を待つ。

**期待結果**

- 選択中の駒と合法な移動先が区別できる。
- 非合法なマスを押しても不正な局面にならない。
- 着手後に手番と棋譜が更新される。
- AI思考中であることが分かり、完了後に応手が表示される。

**UX観察**

- 合法手マーカーは木目盤上で十分に見えるか。
- 選択、直前手、最善手の色が混同しないか。
- AI思考中にフリーズと誤解しないか。
- クリック対象となるマスの大きさは十分か。

### CU-04 投了と新規対局

**目的**: 対局終了と再開始の挙動を確認する。

**手順**

1. 1手以上指す。
2. 「投了」を押す。
3. 結果表示、盤操作、棋譜保存・解析ボタンを確認する。
4. 「新規対局」を押す。

**期待結果**

- 投了者と勝者が正しく表示される。
- 終局後に必要な棋譜操作と解析が可能になる。
- 新規対局で盤面と状態が初期化される。

**UX観察**

- 投了が確認なしで即時実行されても不安がないか。
- 終局したことが視覚的に十分強く伝わるか。
- 新規対局による棋譜消失を予測できるか。

### CU-05 盤反転

**目的**: 盤反転時の座標・駒向き・操作整合性を確認する。

**手順**

1. 初期局面で「盤反転」を押す。
2. 筋・段の順序、王／玉、先後の駒向きを見る。
3. 反転状態で1手指す。
4. 再度反転する。

**期待結果**

- 盤、座標、駒の表示が一貫して180度反転する。
- 手前側の駒が読みやすい向きになる。
- 反転しても選択マスと着手結果が正しい。

**UX観察**

- 盤反転の結果を即座に理解できるか。
- 持ち駒の向きと盤上の駒向きに違和感がないか。

### CU-06 KIF読込（正常系）

**目的**: 外部棋譜を迷わず取り込めるか確認する。

**手順**

1. 「KIF読込」を押す。
2. 「テスト用KIF」を貼り付ける。
3. 読込を確定する。
4. 盤面、手数、棋譜一覧、終局情報を確認する。

**期待結果**

- 全5手として読み込まれる。
- 3手目の角成と5手目の角打ちが盤面に反映される。
- 読込成功が明確に通知される。
- KIF保存、URL共有、棋譜解析が利用可能になる。

**UX観察**

- モーダル内で入力方法が分かるか。
- 読込ボタンとキャンセル操作を見つけやすいか。
- 成功通知が短すぎたり、見落としやすかったりしないか。

### CU-07 KIF読込（異常系）

**目的**: 入力エラーから復帰できるか確認する。

**手順**

1. 「KIF読込」を開く。
2. 「不正入力」のKIFを貼り付ける。
3. 読込を実行する。
4. エラー表示後、正常なKIFに修正して再試行する。

**期待結果**

- アプリが停止せず、読み込み失敗の理由が表示される。
- 元の局面が壊れない。
- 入力を修正して再試行できる。

**UX観察**

- エラー文が利用者向けの言葉になっているか。
- エラーが入力欄の近くに残るか、一時通知だけで消えるか。

### CU-08 棋譜移動とキーボード操作

**目的**: 過去局面の閲覧と現在位置の把握を確認する。

**前提**: 正常なテスト用KIFを読み込み済み。

**手順**

1. `|<`、`<`、`>`、`>|` を順に使用する。
2. 棋譜一覧から任意の手を選ぶ。
3. キーボードの左右矢印で局面を移動する。

**期待結果**

- 盤面、現在手数、棋譜一覧の選択位置が同期する。
- 先頭・末尾では使用不能なボタンが適切に無効化される。
- 左右矢印でも同じ結果になる。

**UX観察**

- 記号だけのナビゲーションボタンの意味が分かるか。
- 現在見ている局面と実戦の最終局面を混同しないか。
- 棋譜が長い場合に現在手を追いやすいか。

### CU-09 棋譜解析と最善手

**目的**: 解析開始から結果閲覧までの一連の体験を確認する。

**前提**: 正常なテスト用KIFを読み込み済み。

**手順**

1. 「棋譜解析」を押す。
2. 解析中の進捗と中止操作を確認する。
3. 解析完了まで待つ。
4. 各局面を前後し、最善手、矢印、評価値グラフ、悪手表示を見る。

**期待結果**

- 解析中であることと進捗が表示される。
- 完了後、表示中局面の最善手が文字と盤上の矢印で示される。
- 局面移動に合わせて最善手と評価が更新される。
- 実戦手と一致する場合は一致表示が出る。

**UX観察**

- 「この局面」がどの手の前後を指すか誤解しないか。
- 最善手の矢印が駒や合法手表示を隠さないか。
- 評価値の正負がどちら側に有利か理解できるか。
- 解析時間に対して待機体験が十分か。
- スマートフォン幅で盤と解析結果が離れすぎないか。

### CU-10 URL共有

**目的**: 棋譜共有の成功と復元性を確認する。

**前提**: 1手以上の棋譜がある。

**手順**

1. 「URL共有」を押す。
2. 成功通知を確認する。
3. コピーされたURLを新しいタブで開く。
4. 手数、棋譜、最終局面を元画面と比較する。

**期待結果**

- URLのコピー成功が通知される。
- 新しいタブで同じ棋譜が復元される。
- サーバーへのログインを要求されない。

**UX観察**

- URLに棋譜が含まれることや、共有範囲を理解できるか。
- コピー後に次に何をすればよいか分かるか。

### CU-11 KIF保存

**目的**: 棋譜をファイルとして保存できるか確認する。

**前提**: 1手以上の棋譜がある。

**手順**

1. 「KIF保存」を押す。
2. ダウンロード開始とファイル名を確認する。
3. 保存したKIFを「KIF読込」で再度読み込む。

**期待結果**

- KIFファイルが1件ダウンロードされる。
- 再読込後に同じ手数と局面が復元される。

**UX観察**

- ファイル名から内容を識別できるか。
- 保存が完了したことが画面上で分かるか。

### CU-12 狭い画面での操作

**目的**: 小さい画面でも主要フローが成立するか確認する。

**手順**

1. Chromeのウィンドウをスマートフォン相当まで狭める。
2. 初期画面の上から下まで確認する。
3. 1手指し、棋譜を開き、解析を開始する。
4. 盤反転を行う。

**期待結果**

- 横スクロールなしで盤全体を見られる。
- 駒と座標を判別できる。
- ボタンや選択欄が重ならない。
- 盤上のマスを誤タップしにくい。

**UX観察**

- 盤と手番表示・持ち駒が同時に見えるか。
- 盤から解析結果までの縦移動量が過大でないか。
- ヘッダーや説明文が主要操作より場所を取りすぎないか。

### CU-13 キーボードフォーカスと読み上げ可能性

**目的**: マウス以外でも主要操作に到達できるか確認する。

**手順**

1. ページ先頭からTabキーで移動する。
2. フォーカス位置を目視確認する。
3. プレイヤー選択、主要ボタン、持ち駒に到達する。
4. 盤上のマスにキーボードで到達できるか確認する。

**期待結果**

- フォーカス位置が視覚的に分かる。
- 操作順が画面の読み順と大きく矛盾しない。
- 各ボタンの名称が意味を持つ。

**UX観察**

- 盤上操作がマウス専用になっていないか。
- 無効ボタンが多く、Tab移動の理解を妨げないか。

## 6. 探索チャーター

上記の手順テスト後、10〜15分間、手順を固定せず次を意識して自由操作する。

1. **初見性**: 説明なしで対局を始め、終え、解析できるか
2. **誤操作耐性**: 同じボタンの連打、局面移動中の着手、解析中の別操作
3. **一貫性**: 選択色、直前手、最善手、悪手表示が意味ごとに統一されているか
4. **フィードバック**: AI思考、解析、コピー、読込、保存の開始・成功・失敗が伝わるか
5. **情報密度**: 盤、棋譜、設定、解析の優先順位が利用場面に合うか
6. **復帰性**: 操作を間違えた後、元の状態へ戻る方法が分かるか

## 7. 改善点の記録テンプレート

```text
ID: UX-001
関連テスト: CU-03
優先度: P2
環境: ENV-01
観察事実:
  歩を選択したが、合法手の丸が木目と重なり2秒ほど見つけられなかった。
期待:
  選択直後に移動可能なマスを迷わず認識できる。
再現手順:
  1. 初期局面で7七の歩を選択
  2. 盤を見る
証拠:
  スクリーンショット名または時刻
提案:
  合法手マーカーのサイズ・縁取り・コントラストを比較検討する。
```

## 9. 完了条件

- CU-01〜CU-13の各ケースに判定がある。
- FailとBlockedには再現手順がある。
- UX改善候補には、主観だけでなく観察事実がある。
- 重大度P1以上の問題はスクリーンショットまたは明確な状態記録がある。
- 最後に、改善候補を「今すぐ直す3件」「後で検討」「現状維持」に分類する。
